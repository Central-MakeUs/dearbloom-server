> **ADR-022 · Domain · Accepted · 2026-08-16**
> "안 읽음"을 어떻게 저장할지 결정. 채팅과 공동보드 댓글이 서로 다른 방식을 쓴다. → **채팅은 방 행의 역할별 카운터, 공동보드 댓글은 참여자 행의 마지막 읽은 시각 커서. 참여자 수가 고정 2명이냐 N명이냐가 갈랐다.**

## 맥락
- 두 곳 모두 "안 읽은 개수 뱃지 + 읽음 처리" 라는 같은 UX 를 요구한다.
- **채팅은 1:1 고정**이다. 고객 한 명, 작가 한 명([[ADR-012 채팅 - 1대1 방·메시지 + 문의 자동연동 + WebSocket 수신]]).
- **공동보드는 참여자가 N명**이다. 초대로 계속 늘어난다([[ADR-016 공동보드 - 보드당 작품 1회 담기와 보드 단위 댓글]]).
- 채팅에는 "상대가 읽었는지"(읽음 표시)까지 필요하지만, 공동보드 댓글에는 없다.

## 결정
### 채팅 — 방 행에 역할별 카운터
```
ChatRoom.customerUnread / artistUnread
ChatRoom.customerLastReadAt / artistLastReadAt
```
- 참여자가 2명 고정이라 **컬럼 2쌍으로 끝난다.** 방 행 하나만 읽으면 목록 뱃지가 나온다.
- 새 메시지 → 수신자(발신자의 반대편) 카운터 `+1`. 읽음 → 그 역할 카운터 `0` + 시각 갱신.
- **읽음 표시는 메시지별 컬럼 없이 판정한다** — 수신자가 한 명뿐이라 `발신 시각 <= 수신자의 마지막 읽은 시각` 이면 읽은 것이다. 메시지 수만큼 행이 늘지 않는다.
- 읽음 상태 변화는 **실시간 브로드캐스트**한다(상대 화면의 "읽음"이 즉시 바뀌어야 함).

### 공동보드 댓글 — 참여자 행에 시각 커서
```
SharedMember.lastReadCommentAt   // null 이면 한 번도 안 읽음
```
- 참여자가 N명이라 **보드 행에 카운터를 둘 수 없다.** 사람마다 따로 관리해야 하므로 `(보드 × 참여자)` 행인 `SharedMember` 에 둔다.
- 안읽음 수는 **조회 시점에 센다** — `그 시각 이후 + 내가 쓴 것 제외`.
- 읽음 처리는 커서를 지금 시각으로 옮기는 것뿐이다.

## 검토한 대안
| 대안 | 기각 이유 |
|---|---|
| 공동보드도 카운터 방식 | 참여자가 N명이라 컬럼을 미리 못 만든다. 댓글 하나에 **참여자 수만큼 UPDATE** 가 나가고, 참여자가 들어오고 나갈 때마다 카운터를 맞춰야 한다 |
| 채팅도 커서 방식 | 목록 뱃지를 그릴 때마다 방마다 메시지를 세야 한다. **2명 고정이라 카운터가 더 싸고 정확하다** |
| 읽음 상태를 별도 테이블로 통일(`read_state`) | 두 도메인의 특성이 달라 통일해도 각자 다른 쿼리를 쓴다. 테이블만 하나 늘고 얻는 게 없다 |
| 메시지마다 `isRead` 컬럼 | 1:1 이라 수신자가 한 명뿐이다. 메시지 수만큼 UPDATE 가 나가는데 시각 비교로 같은 답이 나온다 |
| 안읽음 수를 Redis 로 | DB 와 이중 소스가 되어 정합성 코드만 는다. 채팅은 이미 컬럼이라 조회가 방 행 하나, 보드는 COUNT 한 번이라 이득이 없다 |

## 결과 (트레이드오프)
- ✅ 채팅 목록이 **방 행만 읽고** 뱃지를 그린다(메시지 테이블 미조회).
- ✅ 공동보드는 참여자가 늘어도 스키마가 그대로다.
- ✅ 읽음 표시(채팅)가 메시지별 행 없이 시각 비교로 나온다.
- ⚠️ **채팅 카운터는 파생값이라 어긋날 수 있다.** 메시지는 저장됐는데 카운터 UPDATE 가 유실되면 뱃지가 실제와 다르다(같은 트랜잭션이라 지금은 안전하지만, 나중에 메시지 저장을 비동기로 바꾸면 깨진다).
- ⚠️ **공동보드는 안읽음을 조회할 때마다 센다.** 댓글이 많아지고 뱃지를 자주 갱신하면 COUNT 부담이 생긴다 — 그때는 `(보드, 작성시각)` 인덱스를 확인할 것.
- ⚠️ **같은 개념을 두 방식으로 구현했다.** 세 번째 도메인에 "안읽음"이 생기면 어느 쪽을 따를지 다시 판단해야 한다 — 판단 기준은 **참여자 수가 고정인가**다.
- ⚠️ 읽음 커서가 시각 기반이라 **서버 시계에 의존**한다. 같은 초에 달린 댓글은 읽음/안읽음 경계가 모호할 수 있다.
